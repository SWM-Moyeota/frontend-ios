# Android 와 다른 점

플랫폼 때문에 원본과 다르게 동작하는 부분만 적는다. 한 줄에 하나.

- `Diagnostics.report` 는 취소를 되던지려고 `throws` 이고, `URLSession` 이 던지는 `URLError(.cancelled)` 도 취소로 본다. 「보고 안 하는 전송 실패」(원본 `IOException`)는 `URLError`·POSIX·CFNetwork 도메인 오류와 `MoyeotaDomain.IOException` 이다.
- 요청 JSON 의 키 순서는 선언 순서가 아니라 알파벳순이다(`JSONEncoder` 는 선언 순서를 지키지 않아 `.sortedKeys` 로 고정한다). JSON 객체는 순서가 없어 서버 계약은 같다.
- 업데이트 게이트는 `GET /api/v1/config` 의 `minVersionCode`·`recommendedVersionCode` 를 읽지 않고 `iosMinVersionCode`·`iosRecommendedVersionCode` 를 읽어 `AppConfig` 의 같은 자리로 옮긴다. 앞의 두 키는 Android `versionCode` 수열이라 iOS 빌드 번호와 비교할 수 없다. 키가 없으면 null 이고 아무도 막지 않는다.

- 재설치 후 첫 실행에는 Keychain 의 세션 항목을 지운다. iOS Keychain 은 앱을 지워도 남아 Android 의 「앱 삭제 = 데이터 삭제」와 달라지므로, 앱과 함께 지워지는 `UserDefaults` 표시(`moyeota_session_keychain_install_marker`)가 없으면 남은 항목을 지운 뒤 표시를 남긴다. 지우기가 실패하면(첫 잠금 해제 전 등) 세션을 읽지 않고 미로그인으로 시작하며 다음 실행에 다시 시도한다.
- 토큰은 평문 DataStore 가 아니라 Keychain(`kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`)에 저장하고, 진행 중인 방은 `UserDefaults` 에 저장한다. 첫 잠금 해제 전에는 세션을 읽을 수 없어 미로그인으로 시작한다.
- `URLSession` 은 연결 타임아웃을 따로 두지 못한다. API 는 원본의 연결 10초·읽기/쓰기 20초를 20초 하나로 합치고, 이미지는 연결 10초·읽기 15초를 15초 하나로 합친다. SSE 는 45초다. 죽은 서버에 연결을 시도할 때만 실패가 원본보다 늦게 드러난다.
- 전송 실패의 자동 재시도(OkHttp `retryOnConnectionFailure`)는 `URLSession` 자체 규칙을 따른다. 401·408·503(`Retry-After: 0`) 후속 요청은 원본과 같게 직접 구현했다.
- 채팅 웹소켓의 연결 타임아웃 10초에는 TCP·TLS 연결뿐 아니라 HTTP 업그레이드 응답까지 들어간다. `URLSession` 이 둘을 나눠 재지 못해서다(원본의 업그레이드 응답은 STOMP 연결 전체 15초에만 묶인다). 업그레이드가 10초 넘게 걸리는 서버에서는 원본이 붙을 때 실패하고 재연결로 넘어간다.
- 채팅 수집이 취소돼도 별도 태스크에서 UNSUBSCRIBE → DISCONNECT → RECEIPT 대기(200ms) → Close 1000 순서로 닫는다. 원본은 취소된 코루틴 안에서 `disconnect()` 를 불러 프레임이 나가지 못하고 소켓이 남을 수 있다(바이트코드로 추정한 것이고 실기기로 확인하지는 않았다).
- 이미 닫히는 중인 소켓으로 `ChatSocket.sendMessage`·`markAsRead` 를 부르면 false 다. 원본은 OkHttp `send` 의 거절을 보지 않아 그 짧은 틈에 true 를 돌려주고 프레임을 잃는다. iOS 는 호출부가 REST 로 보낸다.
- `Sec-WebSocket-Protocol` 은 `URLSession` 이 `v12.stomp, v11.stomp, v10.stomp` 로 잇는다(OkHttp 는 공백 없이 쉼표). HTTP 목록으로는 같은 값이다.
- 바이너리 STOMP 프레임의 본문은 늘 UTF-8 로 읽는다. 원본은 `content-type` 에서 문자셋을 찾지 못하면 세션을 끝낸다. 서버는 텍스트 프레임만 보내므로 실제로 갈리지 않는다.
- SSE 줄 끝은 `event`·`id` 줄에서도 `\r` 단독을 인정한다(표준대로). okhttp-sse 는 이 두 줄에서 `\n` 까지 읽는다. 서버(Spring)는 `\n` 만 보내므로 실제로 갈리지 않는다.
- 채팅 소켓 재연결 보고의 `last=` 는 Java 클래스 이름 대신 Swift 타입 이름이고, `URLError` 등 `NSError` 로 올라오는 실패는 `NSURLErrorDomain(-1004)` 처럼 도메인과 코드다.
- 기억해 둔 방 id 는 `Int64(String)` 으로 읽어 ASCII 숫자만 받는다. 원본 `toLongOrNull` 은 유니코드 숫자(`٣` 등)도 받지만, 앱이 심는 값은 서버 PK 를 옮긴 ASCII 문자열뿐이라 실제로 갈리지 않는다.
- 합류 409 의 멤버십 복구 조회(`RemoteRideRepository.recoverMembership`) 중 취소되면 취소를 그대로 던진다. 원본은 `runCatching` 이 취소를 삼켜 `PartyJoinException` 으로 올린다. Swift 태스크는 코루틴과 달리 취소돼도 던진 값이 그대로 호출부에 닿아 화면 이탈이 합류 실패로 보이므로, 같은 파일의 다른 호출과 같게 맞췄다.
- 모든 요청에 빈 `Accept-Language:` 가 실린다. 원본은 이 헤더가 없다. `URLSession` 은 헤더를 빼지 못하고 그대로 두면 기기 언어를 채우므로 빈 값으로 막았다. Tomcat·Spring 은 빈 값을 없는 것과 같게 서버 기본 로케일로 처리한다(라이브러리 동작을 근거로 판단했고 운영 서버로 확인하지는 않았다).
- `Accept: */*`, `Accept-Encoding: gzip, deflate`(HTTPS 에서는 `br` 포함 가능), `User-Agent: … CFNetwork/…` 는 `URLSession` 이 채운다. 원본은 `Accept` 가 없고 `Accept-Encoding: gzip`, `User-Agent: okhttp/x` 다. `Accept` 없음과 `*/*` 는 뜻이 같고, 압축은 전송 계층이 풀며, 서버는 `User-Agent` 를 읽지 않는다.
- `for try await` 로 흐름을 수집하다 취소되면 오류 없이 루프가 끝난다. 원본 `collect` 는 `CancellationException` 을 던진다. `AsyncThrowingStream` 의 성질이라 바꿀 수 없어, 루프 뒤 코드가 「종결」을 뜻하는 곳(대기 화면의 `streamEnded`)은 `try Task.checkCancellation()` 을 먼저 부른다.
- 디버그 로깅에서 SSE 의 2xx 아닌 응답 본문은 찍히지 않는다(`0-byte body` 로 나온다). 원본은 로깅 인터셉터가 본문을 미리 읽어 찍는다. 릴리즈 동작은 양쪽 모두 본문을 읽지 않는다.
- `URLSession` 은 본문이 있는 응답의 상태 코드를 본문 첫 바이트가 올 때까지 내주지 않는다(HTTP/1.1 루프백으로 확인, `bytes(for:)`·델리게이트 모두). 그래서 SSE 의 403·404·401 이 헤더만 오고 본문 첫 바이트 전에 멈추면 원본과 달리 45초 뒤 끊김으로 올라가 재연결한다. 첫 바이트가 온 뒤의 멈춤은 상태 코드로 바로 판정한다.
- 눌림 표시는 머티리얼 잉크 리플 대신 CTA 는 상태 레이어 오버레이(10%), 아이콘·탭·칩은 투명도(60%)다. 리플을 그리는 시스템 부품이 iOS 에 없다.
- 글자 크기는 고정 pt 다(`sp → pt 1:1`). 원본 sp 는 기기 글꼴 배율을 따르지만 iOS 에서는 Dynamic Type 을 따르지 않는다.
- 줄 높이는 `lineSpacing` + 위아래 패딩으로 맞춰서 화면 배율 때문에 지정값과 최대 1/3pt 차이가 난다. 남는 간격은 위아래 절반씩이고, 원본은 어센트·디센트 비율로 나눈다.
- `NaverMapView`·`RouteMapView`·`RouteStripMap` 의 `useTextureView` 는 받기만 하고 쓰지 않는다. iOS SDK 에는 렌더 방식 선택이 없다(Metal).
- 지도의 줌 버튼·나침반은 `NMFMapView` 에 없어 SDK 공개 컨트롤을 직접 얹고 원본 스크린샷에서 잰 여백으로 놓는다. 안전 영역은 무시한다(원본은 `contentPadding` 만으로 놓인다). 이를 위해 `safeAreaInsets` 를 재정의했고, 컨트롤 내용 뷰를 묶으려 첫 하위 뷰에 기댄다(SDK 3.23.3 에서 확인).
- 축척 바는 `NMFScaleView` 대신 안드로이드 `ScaleBarView`(SDK 3.23.3)의 값 고르기·치수를 옮긴 `ScaleBarControl` 이다. `NMFScaleView` 는 기준 폭이 100pt 라 원본(80dp)과 다른 값을 고르고(20 에서 10km 대 5km) 글자가 검정이다. 값을 바꿀 공개 API 가 없다. 숫자 글꼴은 시스템 글꼴이고, 원본의 어두운 지도용 색은 앱이 어두운 지도를 쓰지 않아 옮기지 않았다.
- `MapMarker` 의 `tint` 는 ARGB `Int` 가 아니라 `Color` 다. `LatLng` 은 `NMGLatLng` 가 아닌 값 타입이고 SDK 를 부를 때 `nmgLatLng` 로 바꾼다.
- 지도 카메라 저장(`rememberSaveable`)은 프로세스가 죽으면 사라진다. 뷰가 살아 있으면 지도 자체가 카메라를 들고 있고, 탭처럼 뷰가 없어졌다 다시 생기는 경로는 호출부가 `.environment(\.mapCameraMemory, …)` 를 줘야 복원된다.
- 내 위치 방향 화살표는 iOS SDK 에 공개 상수가 없어 안드로이드 SDK 그림(8×17dp, #1666F0)을 코드로 다시 그렸다.
- 시트 그림자는 안드로이드 앰비언트·스폿 두 겹의 알파(0.039·0.19)를 같게 두되 번짐·거리는 고도에서 환산한 근사다. `Modifier.shadow` 자리의 `moyeotaShadow` 전부 같다.
- 시트를 던졌다고 보는 속도 400px/s 는 pt/s 에 화면 배율을 곱해 비교한다. 3배 화면에서 약 133pt/s 로, 원본의 2.625배 기기(약 152dp/s)보다 조금 민감하다.
- 입력 칸은 `UITextField`·`UITextView` 를 감쌌다. 호출부가 거부한 글자는 표시에 약 50ms 남았다 되돌아간다(`updateUIView` 가 다음 갱신에야 불려 입력 직후의 값을 바로 알 수 없다). 원본에서는 표시되지 않는다.
- 숫자 자판(`number`·`phone`·`numberPassword`·`decimal`)에는 시스템 「완료」 막대를 얹는다. iOS 숫자 자판에는 확인 키가 없어 키보드를 내릴 수 없다. 원본의 확인 키와 같게 `imeAction` 을 실행한다.
- 비밀번호 가림은 iOS 보안 입력이다. `keyboardType = .password` 칸에서 시스템 암호 자동 채우기 제안이 뜰 수 있고, 커서·선택 동작도 시스템 것을 따른다. 점은 시스템이 그려 크기를 정할 공개 API 가 없어 원본의 약 2배다(04a 11자 폭 98pt 대 52dp, 점 높이 6pt 대 2.7dp, 37 11자 폭 약 99pt 대 약 55dp). 보안 입력을 버리고 가림 문자로 맞추지 않았다.
- 위치 갱신 주기는 `CLLocationManager` 에 설정이 없어 시스템 주기(약 1초)를 받아 앱에서 거른다. 원본 `setMinUpdateIntervalMillis(interval / 2)` 와 같은 하한만 지키므로 폼 화면(5초)은 약 3초마다 갱신될 수 있다. 원본의 신규 측위 1회(`getCurrentLocation`)는 `startUpdatingLocation` 의 첫 fix 가 대신하고, Play services 폴백은 없다.
- 위치 권한은 시스템이 한 번만 묻는다. 안드로이드는 한 번 거부한 뒤에도 다시 물을 수 있지만 iOS 는 곧바로 설정 앱으로 보낸다. 버튼을 누르면 시스템이 더 묻지 않는 한(`.notDetermined` 가 아니면) 그 화면이 아직 묻지 않았어도 설정 앱을 연다. 원본 규칙(「이미 물었고 더 물을 수 없으면 설정으로」)의 「이미 물었고」는 진입 시 자동 요청에만 남는다(진입하자마자 설정 앱으로 튀지 않게). 그래서 자동 요청이 없는 21 도착 단계의 「위치 권한 허용」 버튼도 다른 화면(14·17)에서 거부하고 왔으면 첫 탭에 설정 앱을 연다. 원본은 rationale 로 「아직 안 물었다」와 「영구 거부」를 가르지 못해, 그 화면에서 처음 누르면 늘 다시 요청한다.
- `horizontalAccuracy` 가 음수인 fix 는 버린다. iOS 에서는 좌표 자체가 무효라는 뜻이고, 원본의 「정확도 없음」(좌표는 유효)과 다르다.
- 화면 위치 구독은 `@RememberMyLocationState` 에 `.myLocationEffect` 를 함께 붙여야 시작한다. SwiftUI 프로퍼티 래퍼는 화면의 나타남·사라짐을 볼 수 없다.
- 안내 토스트는 시스템 토스트가 없어 창 위에 UIKit 뷰로 직접 그린다(3.5초, 어두운 알약, 하단 안전 영역 위 64pt). 새 토스트는 앞 토스트를 지운다(원본은 차례로 띄운다). VoiceOver 로도 읽어 준다.
- 문의 메일의 제목·본문은 `mailto:` 쿼리로만 넘긴다. iOS 에는 다른 메일 앱에 넘길 extra 가 없다. 쿼리를 무시하는 메일 앱에서는 제목·본문이 비어 보일 수 있다.
- 문의 메일 본문의 「Android:」 줄은 「iOS:」 로 쓰고, 기기 값은 `iPhone16,2` 같은 기종 식별자다(`UIDevice.model` 은 「iPhone」 뿐이다).
- 알림 설정은 `UIApplication.openNotificationSettingsURLString` 으로 연다. iOS 17 이상만 지원해 원본의 구버전 폴백(앱 상세 설정)은 없다.
- 강제 업데이트 화면의 스토어 이동은 `itms-apps://` → `https://apps.apple.com` 순이다. 앱 번호(`SupportLinks.APP_STORE_ID`)가 비어 있는 동안은 앱 페이지가 아니라 스토어 검색 결과로 간다.
- `appVersionCode` 는 `CFBundleVersion` 을 읽는다. Apple 은 `1.2.3` 꼴을 허용하는데, 정수가 아니면 못 읽은 것으로 보고 아무도 막지 않는다.
- 프로필 조회 태스크가 취소되면 `userName` 을 쓰지 않는다. 원본은 `runCatching` 이 취소를 삼켜 로그아웃 직후 `Resolved(null)` 을 쓸 수 있다(「항상 마지막 요청만 살려 둔다」는 원본 주석의 의도에 맞췄다). 태스크가 살아 있는 `URLError(.cancelled)` 는 원본처럼 실패로 `Resolved(null)` 이다.
- 배너·「채팅 열기」·재시도 버튼의 눌림 표시는 잉크 리플 대신 모양 안을 덮는 검정 10% 오버레이(`PressOverlayStyle`)다.
- 위치 fix 시각은 `elapsedRealtimeNanos` 대신 단조 시계에서 fix 의 나이(벽시계로 잰 값)를 뺀 값이다. 캐시된 fix 가 저장된 뒤 시계를 바꾸면 그 한 건의 나이만 틀어진다.
- 온보딩 01~03 의 CTA 는 상태바 아래 기준으로 원본보다 약 31pt 위에 있다(01 649pt 대 680dp). iPhone 화면이 낮아 위아래 weight 여백이 함께 줄어든 값이고 원본도 화면 높이에 따라 움직인다. 페이지 점까지는 1pt 안쪽으로 같다. 요금 알약은 SF 숫자가 넓어 약 5pt 넓다.
